# VERCETI — приватна спільнота

VERCETI — приватний вебпростір спільноти на Next.js, TypeScript і Supabase. Доступ до акаунтів має надаватися адміністрацією; публічна самореєстрація в інтерфейсі вимкнена.

## Технології
- Next.js 15, React 19, TypeScript.
- Supabase Auth, PostgreSQL і Row Level Security.
- LiveKit для голосових кімнат (за наявності серверних ключів).
- Інтеграції музичного каталогу Audius/Jamendo.

## Локальний запуск

Потрібен Node.js LTS. З папки `VERCETI-starter/verceti`:

```bash
npm install
cp .env.example .env.local
npm run dev
```

У Windows PowerShell:

```powershell
Copy-Item .env.example .env.local
npm install
npm run dev
```

Відкрийте http://localhost:3000.

## Змінні середовища

Заповніть `.env.local` локально та відповідні змінні у Vercel Project Settings → Environment Variables.

Обов'язкові для Supabase:
- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY` — лише серверна змінна, ніколи не додавайте префікс `NEXT_PUBLIC_`.

Для голосових кімнат:
- `NEXT_PUBLIC_LIVEKIT_URL`
- `LIVEKIT_API_KEY`
- `LIVEKIT_API_SECRET`

Для пошуку музики Jamendo:
- `JAMENDO_CLIENT_ID`

Не надсилайте секретні ключі в чат, коміти або публічні файли.

## Налаштування Supabase

У Supabase Dashboard:
1. Перевірте Authentication → Providers → Email. Вимкніть відкриту реєстрацію, якщо акаунти мають створюватися лише адміністрацією.
2. У SQL Editor виконайте `supabase/schema.sql` для основних таблиць і функцій.
3. Виконайте `supabase/profile_access_patch.sql`. Міграція додає поле блокування профілю та виправляє створення профілю з нікнеймом, переданим адміністрацією.
4. Виконайте `supabase/rewards.sql` для щоденної рулетки.
5. Виконайте `supabase/voice_rooms.sql` для голосових кімнат.
6. Виконайте `supabase/support.sql` для звернень до підтримки.
7. Виконайте `supabase/site_features.sql` останнім. Скрипт додає таблиці, індекси, RLS-політики й RPC для чату, приватних повідомлень, анкет, новин, правил, тестування, музики, медіа та обліку активності; також посилює перевірку блокувань і узгоджує видалення облікових записів із призами рулетки.

SQL-скрипти модулів потрібно запускати окремо. Перед повторним застосуванням основної `schema.sql` перевірте її вміст: вона містить створення типів і базових об'єктів та не призначена для бездумного повторного запуску.

## Створення першого адміністратора

1. Створіть першого користувача через Supabase Dashboard → Authentication → Users → Invite user або інший контрольований адміністративний спосіб.
2. Переконайтеся, що тригер створив профіль у `public.profiles`.
3. Призначте роль `admin` довіреному першому адміністратору через SQL Editor, перевіривши правильний UUID користувача:

```sql
update public.profiles
set role = 'admin'
where id = 'UUID_КОРИСТУВАЧА';
```

Не призначайте роль адміністратора неперевіреним акаунтам. Після цього адміністратор може створювати облікові записи через панель `/admin`.

## Поточний стан і перевірки

У репозиторії реалізовані модулі входу, профілів і ролей, анкет, новин, подій, сповіщень, правил, чату, приватних повідомлень, тестування, музики, медіатеки, активності, підтримки, рулетки та голосових кімнат. Перед запуском усі SQL-скрипти потрібно застосувати до тієї самої Supabase-бази й перевірити на реальному середовищі.

Перед відкриттям спільноти обов'язково перевірити:
- RLS-політики та права кожної ролі;
- блокування акаунтів у всіх сторінках і API;
- створення та вхід у щойно створені акаунти;
- таблиці та SQL-міграції кожного модуля;
- роботу чату, LiveKit, музики, медіа й обліку активності;
- резервне копіювання та видалення персональних даних.
